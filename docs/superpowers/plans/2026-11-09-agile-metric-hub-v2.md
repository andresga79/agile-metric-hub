> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the v2 dashboard (Portafolio, Equipo, Sprint) on `/v2`, next to the current app, fed by two new API endpoints that compute every figure from one per-sprint base.

**Architecture:** Backend: pure, unit-tested builders in `artifacts/api-server/src/lib/v2/` (window, stats, sprint facts, planning, attention, team and portfolio views) plus one async service that fetches Jira data, caches each team view with `withCache`, and is warmed serially during sync. Frontend: a self-contained `artifacts/dashboard/src/v2/` folder with its own layout and Nxtara dark theme scoped under `.v2-root`, Spanish copy only.

**Tech Stack:** Express 5, TypeScript 5.9, vitest, Drizzle (thresholds table), orval codegen, React + wouter + react-query + Tailwind, lucide-react.

**Spec:** `docs/superpowers/specs/2026-11-09-agile-metric-hub-v2-design.md`. Visual reference: `docs/superpowers/specs/v2-reference/` (`Portafolio.dc.html`, `Equipo.dc.html`, `Mapa.dc.html`, `nxt-tokens.css`, `tokens.json`). Read both before starting any task.

## Global Constraints

- Current app unchanged: no edits to existing pages except the "Probar v2" header link (Task 9) and the Admin threshold labels (Task 4). The "Completado = Done hoy" rule of the current screens stays.
- Sprint headline = Rovo number (`isIssueDone`, Done hoy); "% real cerrado" (`wasIssueDoneAt` at `sprintCloseTime`) always next to it. Trends, predictability, planning and attention use **real cerrado only**.
- Sprint scope = `sprintScopeIssues(issues, allowedIssueTypes)` from `routes/sprint-metrics.ts`. Never re-implement the filter.
- Predictability = **sample** std dev (n−1) of per-sprint real rate, in pp; bands alta ≤ 8, media ≤ 12, baja > 12 (thresholds `sprintPredictability` good 8 / warning 12).
- Averages are simple means of per-sprint rates; portfolio average is a simple mean across Scrum teams.
- Cycle-time trends everywhere use the **median**. UI name: "Tiempo de ciclo" (never "Tiempo de entrega").
- Windows: Scrum `sprints=3|6|12` (default 6); Kanban `days=30|90|180` (default 90); Portafolio's Kanban rows always 90 days.
- Trend comparison: Scrum = most recent half of the window vs earlier half (6 → 3 vs 3, 12 → 6 vs 6); with 3, the 3 vs the 3 closed before them. Kanban = window vs the previous window of equal length.
- Attention: Scrum avg real < `sprintCompletionReal.warningValue` (50) OR band "baja"; Kanban throughput drop > `kanbanThroughputDrop.warningValue` (30) OR median cycle rise > `kanbanCycleTimeRise.warningValue` (30). Thresholds read via `getEffectiveThresholds(projectId)`.
- Memory: per-project work runs **one project at a time** (never `Promise.all` across projects). Team views cached with `withCache`, key `v2:team:<projectId>:<s6|d90…>`.
- Copy in Spanish, no i18next in `/v2`; numbers es-CL (decimal comma); minus sign `−` (U+2212) in deltas.
- Nxtara styles only under `.v2-root`; fonts MuseoModerno (titles) + Jost (text); icons lucide-react; no new npm dependencies.
- Process: `pnpm run typecheck`, `pnpm --filter @workspace/api-server test`, `pnpm run lint` (0 errors, ≤ 140 warnings) before every commit. Never push.

## Review Focus

1. A team with fewer closed sprints than the window (e.g. 2 closed, window 6) → shows what exists; trend deltas `null` ("sin dato previo"); predictability `null` with < 2 sprints; planning `null` with < 3 closed. Test in Task 5.
2. A sprint with no story points (`basis: "issueCount"`) next to SP sprints → its rates use issue count; SP sums skip it; planning still gives issues. Test in Task 4.
3. No active sprint (between sprints) → `active: null`, header says "Sin sprint en curso", page renders. Test in Task 5; UI in Task 11.
4. One project failing in Jira → its portfolio row has `error` and the rest render; the summary cards ignore it. Test in Task 7.
5. Previous period with zero delivered or no cycle data → deltas `null`, never `Infinity`/`NaN`, and a `null` delta never triggers attention. Tests in Tasks 1 and 4.
